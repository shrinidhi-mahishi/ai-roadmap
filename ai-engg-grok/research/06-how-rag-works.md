# Research: How RAG Works

**Date researched**: 2026-09-30
**Sources consulted**: 28

## 1. System Topology & Mechanics

Retrieval-Augmented Generation (RAG) is an architectural pattern that couples a **parametric** language model with a **non-parametric** external knowledge index. Lewis et al. (NeurIPS 2020) formalize this as: a pre-trained seq2seq generator (BART-large, 400M params) conditioned on passages retrieved from a dense Wikipedia index via a neural retriever (DPR bi-encoder + FAISS MIPS / HNSW), treating retrieved documents as latent variables that are marginalized at generation time ([Lewis et al., 2020 — arXiv](https://arxiv.org/abs/2005.11401); [NeurIPS PDF](https://proceedings.neurips.cc/paper/2020/file/6b493230205f780e1bc26945df7481e5-Paper.pdf)).

### Control plane vs. data plane

| Plane | Responsibility | Concrete components |
| --- | --- | --- |
| **Control plane** | Ingestion triggers, index versioning, ACL/metadata policy, retrieval strategy selection (sparse / dense / hybrid), top-K / rerank budgets, query routing (agentic) | Offline job schedulers; index swap / blue-green corpora; auth → filter compilation; agent router / CRAG evaluator ([System Design Newsletter — How RAG Works](https://newsletter.systemdesign.one/p/how-rag-works); [Anthropic Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval); [AWS Bedrock metadata filtering](https://aws.amazon.com/blogs/machine-learning/access-control-for-vector-stores-using-metadata-filtering-with-knowledge-bases-for-amazon-bedrock/)) |
| **Data plane** | Chunk → embed → ANN/BM25 search → fuse → rerank → prompt assemble → LLM generate | Embedding workers; inverted + vector indexes; RRF merger; cross-encoder / Cohere reranker; LLM prefill/decode ([Lewis et al., 2020](https://arxiv.org/abs/2005.11401); [Elastic hybrid retrieval](https://www.elastic.co/search-labs/blog/improving-information-retrieval-elastic-stack-hybrid)) |

### Offline ingestion vs. online retrieval (canonical topology)

Production RAG splits into two pipelines ([System Design Newsletter — How RAG Works](https://newsletter.systemdesign.one/p/how-rag-works); [Anthropic Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval)):

1. **Offline (ingestion)**: load documents → **chunk** → (optional contextualize) → embed + build BM25/TF-IDF → store vectors + metadata → version the index.
2. **Online (query)**: embed query with the **same** embedding model → sparse + dense retrieval → fuse (RRF / weighted sum) → optional rerank → assemble prompt (system + retrieved chunks + user query) → generate with citations.

Lewis et al. compare two marginalization topologies: **RAG-Sequence** (one retrieved doc for the whole answer) vs. **RAG-Token** (different docs can contribute per token). Non-parametric memory is a Dec 2018 Wikipedia dump split into **21,015,324** disjoint ~100-word chunks; they retrieve \(k \in \{5,10\}\) at train time and up to **15** (Token) / **50** (Sequence) at test for open-domain QA ([Lewis et al., 2020](https://arxiv.org/abs/2005.11401)).

### Retrieval strategies (sparse / dense / hybrid)

- **Sparse (BM25)**: lexical TF–IDF with length normalization and term-frequency saturation; strong on exact IDs / error codes / rare terms that embeddings miss (e.g. `"Error code TS-999"`) ([Anthropic Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval)).
- **Dense**: bi-encoder embeddings + ANN (MIPS / HNSW / IVF); semantic match across paraphrase ([Lewis et al., 2020](https://arxiv.org/abs/2005.11401); [FAISS HNSW](https://github.com/facebookresearch/faiss/wiki/Faiss-indexes)).
- **Hybrid**: run both, then fuse. Anthropic’s production-style recipe: BM25 top chunks + embedding top chunks → combine/dedupe via **rank fusion** → optionally rerank → pass top-K to the LLM ([Anthropic Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval)).

**Reciprocal Rank Fusion (RRF)** (Cormack et al., 2009; used in Elastic): \(\mathrm{score}(d)=\sum_i 1/(k+\mathrm{rank}_i(d))\). Elastic’s BEIR subset experiments found RRF of BM25 + Elastic Learned Sparse Encoder lifted average **nDCG@10 by 1.4%** over sparse-encoder alone and **18%** over BM25 alone; per-dataset ideal linear fusion of normalized scores reached **+6% / +24%** nDCG@10 vs those baselines, but needs ~40–300 annotated queries for calibration ([Elastic hybrid retrieval](https://www.elastic.co/search-labs/blog/improving-information-retrieval-elastic-stack-hybrid)).

### Contextual retrieval (chunk enrichment before indexing)

Anthropic’s **Contextual Retrieval** prepends 50–100 tokens of chunk-specific context (generated by Claude Haiku from the full document) before embedding **and** before BM25 indexing. On their multi-domain eval (codebases, fiction, ArXiv, science), with Gemini Text 004 embeddings and top-20 retrieval, failure rate (\(1-\mathrm{recall}@20\)) moved ([Anthropic Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval)):

| Pipeline | Failure @20 | Relative reduction |
| --- | --- | --- |
| Baseline dense | 5.7% | — |
| Contextual Embeddings | 3.7% | **35%** |
| Contextual Embeddings + Contextual BM25 | 2.9% | **49%** |
| Above + Cohere rerank (candidates→top-20 from top-150) | 1.9% | **67%** |

They also report: Voyage/Gemini embeddings strongest among tested; top-20 chunks to the model beat top-5/top-10; all gains stack ([Anthropic Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval)).

### Chunking mechanics

Lewis et al. used fixed ~100-word Wikipedia passages ([Lewis et al., 2020](https://arxiv.org/abs/2005.11401)). Anthropic recommends chunks of “a few hundred tokens” and notes boundary/overlap choices matter ([Anthropic Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval)). Empirical chunking research:

- **Fixed-size / recursive** (≈300–512 tokens, 10–20% overlap) remains the practical default; NAACL 2025 Findings conclude semantic chunking’s compute cost is **not consistently justified**—on non-synthetic corpora fixed-size often matches or beats semantic splitters ([Qu et al., 2025 — “Is Semantic Chunking Worth the Computational Cost?”](https://aclanthology.org/2025.findings-naacl.114.pdf)).
- **Parent-child / hierarchical (RAPTOR)**: retrieve small children, expand to parent context; RAPTOR tree-organized retrieval for multi-hop ([Sarthi et al., 2024 — arXiv 2401.18059](https://arxiv.org/abs/2401.18059)).
- **Late chunking**: embed full doc with long-context embedder, then pool per-chunk vectors ([Günther et al., 2024 — arXiv 2409.04701](https://arxiv.org/abs/2409.04701)).

### Vector-index internals (summary only)

Dense retrieval uses ANN over embedding space. FAISS **HNSW** (`IndexHNSWFlat`): graph with \(M\) neighbors/vector; `efSearch` trades recall vs latency. On SIFT1M (20 threads), published FAISS bench: `efSearch=16` → **0.011 ms/query**, R@1 **0.874**; `efSearch=64` → **0.033 ms**, R@1 **0.978**; memory ≈ \(4d + 8M\) bytes/vector ([FAISS Indexing 1M vectors](https://github.com/facebookresearch/faiss/wiki/Indexing-1M-vectors); [FAISS indexes wiki](https://github.com/facebookresearch/faiss/wiki/Faiss-indexes)). Lewis et al. used FAISS HNSW for MIPS over 21M Wikipedia passages ([Lewis et al., 2020](https://arxiv.org/abs/2005.11401)). **[Deferred]** full vector-DB ops (sharding, replication, multi-tenancy) belong to a later roadmap topic.

### Agentic RAG topologies

Naive RAG is a fixed retrieve→generate DAG. **Agentic RAG** adds a reasoning/control loop that can reformulate queries, choose indexes, retry, grade evidence, or skip retrieval ([System Design Newsletter — How RAG Works](https://newsletter.systemdesign.one/p/how-rag-works); [Agentic RAG survey](https://arxiv.org/html/2501.09136v4)):

| Pattern | Control structure | Key published signal |
| --- | --- | --- |
| **Self-RAG** (Asai et al., ICLR 2024) | LM emits reflection tokens (`Retrieve`, `ISREL`, `ISSUP`, `ISUSE`); adaptive retrieve + critique | Self-RAG 7B: PopQA **54.9**, TriviaQA **66.4**, PubHealth **72.4**, ARC **67.3**, Bio FactScore **81.2**; citation precision on ASQA **70.3** vs Ret-ChatGPT **39.9** ([Self-RAG paper](https://proceedings.iclr.cc/paper_files/paper/2024/file/25f7be9694d7b32d5cc670927b8091e1-Paper-Conference.pdf)) |
| **CRAG** (Yan et al., 2024) | Lightweight retrieval evaluator → Correct / Ambiguous / Incorrect actions; web search fallback; decompose-then-recompose | On SelfRAG-LLaMA2-7b: CRAG PopQA **59.8** vs RAG **52.8**; Biography FactScore **74.1** vs **59.2**; PubHealth **75.6** vs **39.0** ([CRAG arXiv](https://arxiv.org/html/2401.15884v3)) |
| **Adaptive / router agents** (LlamaIndex etc.) | Classifier/router picks no-retrieval vs single-shot vs multi-step / which sub-index | Engineering pattern; corpus-specific gains ([LlamaIndex agentic retrieval](https://www.llamaindex.ai/blog/rag-is-dead-long-live-agentic-retrieval)) |

Execution is typically **sync request/response** for single-hop RAG; agentic variants are **multi-step async loops** with per-hop retrieval tool calls and max-iteration guards ([Agentic RAG survey](https://arxiv.org/html/2501.09136v4)).

## 2. Token Economics & NFR Metrics

### Why not stuff the whole corpus

Anthropic: if the knowledge base is **&lt; ~200,000 tokens (~500 pages)**, stuffing the full KB into the prompt (with prompt caching) can beat RAG—caching cuts latency **&gt;2×** and cost **up to 90%**. Beyond that scale, RAG is required ([Anthropic Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval)). Newsletter framing: long-context stuffing is expensive (pay per token every query), hard-capped by window size, and degraded by lost-in-the-middle ([System Design Newsletter — How RAG Works](https://newsletter.systemdesign.one/p/how-rag-works); [Liu et al., 2024](https://arxiv.org/abs/2307.03172)).

### Worked cost: stuffing vs selective RAG `[inferred from published unit prices]`

Assumptions for a Claude-class input rate of **$3 / MTok** input (illustrative mid-tier; verify current vendor SKU before budgeting) and **~500 tokens/chunk**:

| Strategy | Context tokens / query | Input $ / 1k queries | Notes |
| --- | --- | --- | --- |
| Stuff 200K-token KB every query (no cache) | 200,000 | \(200\times\$3=\$600\) | Anthropic’s “small KB” upper bound ([Anthropic Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval)) |
| Same with 90% cache hit on static prefix | ~20,000 billed @ full + 180,000 @ ~0.1× | **[inferred]** ~\$78 / 1k | Matches Anthropic’s “up to 90%” cache claim directionally |
| RAG top-5 chunks | ~2,500 + query/system | \(2.5\times\$3=\$7.50\) | Selective retrieval |
| RAG top-20 chunks (Anthropic’s preferred K) | ~10,000 + query/system | \(10\times\$3=\$30\) | Better recall@20, higher prefill cost ([Anthropic Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval)) |

**Takeaway**: moving from stuffing 200K → RAG top-20 is roughly an order-of-magnitude input-token cut per query when cache is cold; with warm prompt cache on a small static KB, stuffing can be competitive until the corpus outgrows the window ([Anthropic Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval)). `[inferred]` exact $ depends on live SKU prices.

### Index-time costs (Contextual Retrieval)

Anthropic publishes one-time contextualization cost with prompt caching: **$1.02 per million document tokens** under assumptions 800-token chunks, 8K-token documents, 50-token instructions, ~100-token generated context per chunk ([Anthropic Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval)).

### Embedding & rerank unit economics

> ⚠️ Limited public data available for this dimension. Vendor embedding/rerank SKUs and list prices change frequently; treat the following as order-of-magnitude planning anchors and re-check vendor pages at deploy time.

- OpenAI `text-embedding-3-small` commonly listed at **$0.02 / MTok** input (aggregator citing OpenAI pricing as of mid-2026) ([ModelPriceWatch — text-embedding-3-small](https://modelpricewatch.com/models/openai-text-embedding-3-small/)).
- Cohere Rerank billed **per search** (1 query × up to 100 docs); docs define document splitting if &gt;500 tokens. Pay-as-you-go cards have listed Rerank 4 Fast / Pro around **$2.00–$2.50 / 1K searches** (verify live [Cohere pricing](https://cohere.com/pricing); [Cohere pricing docs](https://docs.cohere.com/docs/how-does-cohere-pricing-work.mdx)).
- Anthropic notes reranking top-150→top-20 adds runtime latency; trade more candidates (quality) vs fewer (latency/cost) ([Anthropic Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval)).

### Latency budgets (retrieval stage)

Published micro-benchmarks and engineering budgets (not end-to-end product SLAs):

| Stage | Typical published latency | Source |
| --- | --- | --- |
| FAISS HNSW ANN (SIFT1M, in-process) | **0.01–0.10 ms**/query depending on `efSearch` | [FAISS 1M bench](https://github.com/facebookresearch/faiss/wiki/Indexing-1M-vectors) |
| BM25 (OpenSearch-class, top-100) | **~5–15 ms** `[engineering estimate]` | CalibreOS hybrid guide summarizing production stacks ([CalibreOS hybrid search](https://www.calibreos.com/learn/genai-hybrid-search)) |
| Dense ANN (HNSW service) | **~10–30 ms** `[engineering estimate]` | Same |
| Cross-encoder / managed rerank | **~30–80 ms** p50 incl. network `[engineering estimate]` | Cohere/Voyage-class; Anthropic used Cohere ([Anthropic Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval); [CalibreOS](https://www.calibreos.com/learn/genai-hybrid-search)) |
| Full RAG e2e (retrieval + LLM) | Dominated by LLM TTFT/decode; retrieval often budgeted **100–200 ms** of a multi-second answer `[inferred]` | [CalibreOS](https://www.calibreos.com/learn/genai-hybrid-search) |

Elastic notes hybrid BM25+semantic historically ran queries **sequentially**, increasing query latency vs single retriever ([Elastic hybrid retrieval](https://www.elastic.co/search-labs/blog/improving-information-retrieval-elastic-stack-hybrid)). Industry RAG-Fusion deployment report: fusion path added ~**0.89 s** overhead (extra query gen + RRF + second rerank) and raised **tail** latency even when median stayed acceptable ([RAG Fusion industry paper](https://arxiv.org/pdf/2603.02153)).

### Retrieval quality metrics (nDCG & friends)

| Metric | Role in RAG | Published example |
| --- | --- | --- |
| **nDCG@10** | Graded ranking quality of fused lists | Elastic: RRF +1.4% avg nDCG@10 vs ELSER; ideal weighted sum +6% ([Elastic hybrid](https://www.elastic.co/search-labs/blog/improving-information-retrieval-elastic-stack-hybrid)) |
| **Recall@k / 1−recall@k** | Did any relevant chunk appear in top-k? | Anthropic primary metric: failure@20 5.7%→1.9% ([Anthropic](https://www.anthropic.com/engineering/contextual-retrieval)) |
| **Exact Match (EM)** | Open-domain QA answer match (Lewis) | RAG-Sequence NQ **44.5** EM; TQA **56.1/68.0**; WQ **45.2**; CT **52.2** — SOTA at publication vs DPR extractive ([Lewis et al., 2020](https://arxiv.org/abs/2005.11401)) |
| **Downstream accuracy / FactScore** | End-task after generation | Self-RAG / CRAG tables above |

Lewis et al. did **not** report nDCG; they used EM / F1 / BLEU / ROUGE / human preference ([Lewis et al., 2020](https://arxiv.org/abs/2005.11401)). Modern IR stacks standardize on nDCG@k for retrieval ablations ([Elastic hybrid](https://www.elastic.co/search-labs/blog/improving-information-retrieval-elastic-stack-hybrid)).

### Prompt / semantic caching

- **Prompt caching** of static system + retrieved-context prefixes amortizes repeated RAG prompts; Anthropic cites **&gt;2×** latency and **up to 90%** cost cuts for cached prompts ([Anthropic Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval)).
- **Semantic query cache** (cache answers by embedding similarity of queries): common production pattern but **no universal published hit-rate SLA**—hit rate is corpus- and threshold-specific `[inferred]`.

## 3. Distributed Resilience & State

> ⚠️ Limited public data available for this dimension. Foundational RAG papers and vendor blogs specify index/retrieval mechanics far more than Temporal/Kafka-style durable orchestration, distributed locks, or circuit-breaker thresholds for RAG control planes. Below mixes confirmed patterns with clearly marked inferences.

### What state must be durable

| State | Durability need | Failure if lost |
| --- | --- | --- |
| Document corpus + ACL metadata | Source of truth (object store / CMS) | Silent stale or unauthorized answers |
| Chunk ↔ embedding index version | Atomic swap / dual-write | Partial reindex → mixed embedding spaces |
| Online query logs / retrieval audit | Append-only | Cannot prove who saw which doc ([VaultRAG pattern](https://github.com/AgentPostmortem/VaultRAG)) |
| Agentic loop checkpoints | Optional; needed for long multi-hop jobs | Lost mid-plan → duplicate tool spend `[inferred]` |

### Index consistency & replay

- Lewis et al. demonstrate knowledge updates by **replacing the non-parametric index** without retraining the generator ([Lewis et al., 2020](https://arxiv.org/abs/2005.11401)).
- Production pattern `[inferred from architecture]`: blue/green indexes (build vN+1 offline → atomic alias swap); never mix embedding-model versions in one ANN space.
- CRAG / Self-RAG add **evaluator state** (confidence → action) that should be logged for replay/debug ([CRAG](https://arxiv.org/html/2401.15884v3); [Self-RAG](https://proceedings.iclr.cc/paper_files/paper/2024/file/25f7be9694d7b32d5cc670927b8091e1-Paper-Conference.pdf)).

### Circuit breakers & degradation chains `[inferred + sparse public signals]`

Recommended degradation ladder for enterprise RAG control planes:

1. Skip rerank if reranker p95 &gt; budget → serve RRF top-K.
2. Skip dense if ANN errors → BM25-only (Elastic shows BM25 alone is a safe floor on many BEIR sets) ([Elastic hybrid](https://www.elastic.co/search-labs/blog/improving-information-retrieval-elastic-stack-hybrid)).
3. CRAG-style **Incorrect** retrieval → web search or refuse rather than hallucinate from bad context ([CRAG](https://arxiv.org/html/2401.15884v3)).
4. Cap agentic iterations / max retrieval hops (Self-RAG `max_depth` default **6** in reference impl) ([Self-RAG GitHub](https://github.com/akariasai/self-rag)).

### Rate limiting & back-pressure

Embedding and rerank APIs are TPM/search-rate limited; ingestion should batch embeds and apply token-bucket back-pressure so online query traffic is not starved `[inferred]`. No standard published RAG-specific RPM number across vendors—capacity plan from embedding QPS × dim × index shard count.

## 4. Enterprise Security & Governance

### Document-level RBAC in the retrieval path

Enterprise failure mode: similarity search **ignores** source ACLs unless filters are mandatory inside the query. Patterns with public documentation:

- **Pre-filter in the vector/hybrid query** (not post-trim in app code): attach `allowed_users` / `allowed_groups` / `tenant_id` / classification on every chunk; compile filters from authenticated identity ([AWS Bedrock Knowledge Bases metadata filtering](https://aws.amazon.com/blogs/machine-learning/access-control-for-vector-stores-using-metadata-filtering-with-knowledge-bases-for-amazon-bedrock/); [Truto RBAC guide](https://truto.one/blog/how-to-maintain-document-level-rbac-in-enterprise-rag-pipelines)).
- **Deny-by-default**: chunks with missing ACL rows must be invisible; VaultRAG reports deleting the ACL predicate raised leak rate from **0% → 81.8%** while recall stayed 100% on their gold-set ([VaultRAG](https://github.com/AgentPostmortem/VaultRAG)).
- **Live auth vs stale metadata**: nightly ACL sync leaves revoke windows (employee leaves Monday, sync 2 AM Tuesday) ([Truto](https://truto.one/blog/how-to-maintain-document-level-rbac-in-enterprise-rag-pipelines)). Prefer per-query group resolution from IAM, not client-asserted roles ([VaultRAG](https://github.com/AgentPostmortem/VaultRAG)).

### PII & regulated data

- Redact / de-identify **before** chunk+embed when feasible (NER on full docs beats fragments); HIPAA Safe Harbor / Expert Determination; BAA with vector DB / LLM vendors when PHI is processed ([Scadea RAG security](https://scadea.com/rag-security-and-data-governance-access-control-for-retrieved-context/); [Unolabs securing enterprise RAG](https://unolabs.com/blog/security-frameworks-for-ai)).
- Tools commonly cited: Microsoft Presidio, Amazon Comprehend ([Scadea](https://scadea.com/rag-security-and-data-governance-access-control-for-retrieved-context/)).

### Audit & compliance

Structured audit should record: principal, query, filter decision, chunk IDs returned/denied, model version, index version—immutable enough for SOC2/GDPR access reviews (`"did user Y ever see doc X?"` as a query) ([VaultRAG](https://github.com/AgentPostmortem/VaultRAG); [Unolabs](https://unolabs.com/blog/security-frameworks-for-ai)). GDPR erasure requires coordinated delete across object store **and** vector/BM25 indexes.

### Prompt-injection via retrieved content

Poisoned documents can instruct the generator to ignore policy. Mitigations: treat retrieved text as untrusted data (delimit clearly), content security scanning at ingest, least-privilege tool access for agentic RAG `[inferred from threat model; limited RAG-specific public post-mortems]`.

## 5. Production Failure Modes

### Lost-in-the-middle (context utilization)

Liu et al. (TACL 2024) show U-shaped accuracy vs. position of the answering passage in multi-document QA: primacy + recency bias; middle positions collapse. For GPT-3.5-Turbo, middle placement in 20–30 document settings can fall **below closed-book 56.1%**—i.e. worse than giving **no** documents. Closed-book vs oracle: GPT-3.5-Turbo **56.1% → 88.3%**; Claude-1.3 **48.3% → 76.1%** ([Liu et al., arXiv](https://arxiv.org/abs/2307.03172); [Stanford PDF](https://cs.stanford.edu/~nfliu/papers/lost-in-the-middle.tacl2023.pdf)). Newsletter cites ~**25%** accuracy for some models with key facts mid-pack in 20-doc contexts ([System Design Newsletter — How RAG Works](https://newsletter.systemdesign.one/p/how-rag-works)).

Open-domain case study: reader accuracy **saturates before retriever recall**—going from **20 → 50** retrieved docs gains only ~**1–1.5%** for GPT-3.5-Turbo / Claude-1.3 while blowing up tokens/latency; prefer rerank-to-front or truncate ([Liu et al., 2024](https://arxiv.org/abs/2307.03172)).

**Mitigations**: keep K small but high-precision (Anthropic top-20 after rerank); put highest-rerank scores at prompt edges; query-aware contextualization helps KV tasks more than multi-doc QA ([Liu et al., 2024](https://arxiv.org/abs/2307.03172); [Anthropic Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval)).

### Retrieval miss / wrong neighborhood

- Dense-only misses exact identifiers → hybrid BM25 ([Anthropic](https://www.anthropic.com/engineering/contextual-retrieval)).
- Context-stripped chunks (“revenue grew 3%”) fail company/time queries → contextual embeddings ([Anthropic](https://www.anthropic.com/engineering/contextual-retrieval)).
- CRAG evaluator triggers corrective web search when corpus evidence is wrong/ambiguous ([CRAG](https://arxiv.org/html/2401.15884v3)).

### Hallucination despite RAG

RAG reduces but does not eliminate fabrication:

- Legal-domain study: general LLMs hallucinate **58–82%** on legal queries; commercial legal RAG tools still hallucinate **~17–33%** of queries (Lexis+ / Westlaw / Practical Law) ([Dahl et al. / Stanford legal RAG study](https://dho.stanford.edu/wp-content/uploads/Legal_RAG_Hallucinations.pdf)).
- Grounded summarization leaderboards (Vectara HHEM) show much lower rates for short-doc summarization (often single-digit % depending on model)—task-dependent, not a universal “1%” guarantee ([Vectara hallucination leaderboard](https://github.com/vectara/hallucination-leaderboard)).
- Newsletter’s “1% vs &gt;58%” framing aligns with **task variance** (simple grounded summary vs complex ungrounded/legal work), not a single RAG SLA ([System Design Newsletter — How RAG Works](https://newsletter.systemdesign.one/p/how-rag-works); [legal RAG PDF](https://dho.stanford.edu/wp-content/uploads/Legal_RAG_Hallucinations.pdf)).

### Chunking / embedding drift

Changing chunker, overlap, or embedding model without full reindex yields silent recall regression. Semantic chunkers add ingest CPU/GPU without consistent gains ([Qu et al., 2025](https://aclanthology.org/2025.findings-naacl.114.pdf)). Store `chunk_strategy` + `embedding_model` + `index_version` on every chunk `[inferred ops requirement]`.

### Agentic infinite loops / cost blow-ups

Self-RAG / multi-step agents can re-retrieve repeatedly. Guards: reflection thresholds, `max_depth`, always-on cost caps, and “no retrieval” mode for chitchat ([Self-RAG GitHub](https://github.com/akariasai/self-rag); [Self-RAG paper](https://proceedings.iclr.cc/paper_files/paper/2024/file/25f7be9694d7b32d5cc670927b8091e1-Paper-Conference.pdf)).

### Cascading timeouts

Rerank + multi-query fusion inflate **p99** even when p50 is fine ([RAG Fusion industry](https://arxiv.org/pdf/2603.02153)). Propagate a single deadline budget: embed || BM25 → fuse → rerank → LLM, with stage-level timeouts and bulkheads `[inferred]`.

### ACL / tenancy leaks

Post-retrieval filtering fails open on new code paths; enforce filters inside the retrieval query ([VaultRAG](https://github.com/AgentPostmortem/VaultRAG); [Unolabs](https://unolabs.com/blog/security-frameworks-for-ai)).

## 6. Enterprise System Design Scenarios

### Scenario A — Internal knowledge assistant (10K–500K docs)

**Design**: hybrid BM25+dense → RRF → cross-encoder/Cohere rerank to 10–20 chunks → cite sources; metadata filters for department ACLs.

**Rationale**: Anthropic stack shows failure@20 **5.7% → 1.9%** when contextual hybrid + rerank are combined ([Anthropic Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval)). Elastic shows hybrid nDCG gains without per-query ML tuning when using RRF ([Elastic hybrid](https://www.elastic.co/search-labs/blog/improving-information-retrieval-elastic-stack-hybrid)).

**Capacity sketch `[inferred]`**: 1M chunks × 1536-d float32 ≈ 6 GB vectors before graph overhead; HNSW adds ~\(8M\) bytes/vector ([FAISS guidelines](https://github.com/facebookresearch/faiss/wiki/Guidelines-to-choose-an-index)).

### Scenario B — Regulated / multi-tenant SaaS

**Design**: per-tenant index **or** shared index with mandatory tenant+ACL prefilters; PII redaction pre-embed; audit every retrieval; prompt-injection scanning at ingest ([AWS Bedrock filtering](https://aws.amazon.com/blogs/machine-learning/access-control-for-vector-stores-using-metadata-filtering-with-knowledge-bases-for-amazon-bedrock/); [VaultRAG](https://github.com/AgentPostmortem/VaultRAG)).

**Trade-off**: separate indexes maximize isolation/ops cost; shared+filter maximizes density but demands airtight filter compilation.

### Scenario C — Agentic research over multiple corpora

**Design**: router agent → Self-RAG/CRAG loop with web fallback on low confidence; cap hops; grade `ISSUP` before final answer ([Self-RAG](https://proceedings.iclr.cc/paper_files/paper/2024/file/25f7be9694d7b32d5cc670927b8091e1-Paper-Conference.pdf); [CRAG](https://arxiv.org/html/2401.15884v3); [LlamaIndex agentic retrieval](https://www.llamaindex.ai/blog/rag-is-dead-long-live-agentic-retrieval)).

**Cost note**: each extra retrieval+rerank pass adds tens–hundreds of ms and another embed; fusion papers report ~**0.9 s** class overheads for multi-query fusion paths ([RAG Fusion](https://arxiv.org/pdf/2603.02153)).

### Scenario D — “Just use long context”

**When**: corpus &lt; ~200K tokens and prompt caching available ([Anthropic Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval)).

**When not**: enterprise wikis/databases exceed windows; lost-in-the-middle makes naive stuffing unsafe even inside the window ([Liu et al., 2024](https://arxiv.org/abs/2307.03172)). Hybrid pattern: RAG selects ≤20 chunks, long context reads them.

### Trade-off matrix

| Approach | Retrieval quality | $/query | Latency | Ops complexity | Security |
| --- | --- | --- | --- | --- | --- |
| Stuff small KB + cache | High if fits | Low when cached | Low TTFT when cached | Low | ACL = prompt isolation only |
| Dense-only top-k | Medium | Low–med | Low | Low | Needs metadata filters |
| Hybrid BM25+dense + RRF | High (nDCG↑) | Med | Med | Med | Same + dual index ACL |
| + Contextualize chunks | Higher (fail@20 −49%) | Index-time $1.02/MTok docs | Same online | Med–high | Context may leak titles into index |
| + Rerank | Highest (fail@20 −67%) | +$/search | +30–80 ms | Med | Rerank sees candidates—filter first |
| Agentic (Self-/CRAG) | Best on hard queries | Highest (multi-hop) | Highest / variable p99 | High | Larger attack surface (tools/web) |

### RAG vs fine-tuning (enterprise choice)

Fine-tune for **behavior/format**; RAG for **updatable knowledge** with provenance. Best systems combine both ([System Design Newsletter — How RAG Works](https://newsletter.systemdesign.one/p/how-rag-works); [Lewis et al., 2020](https://arxiv.org/abs/2005.11401) — index swap updates world knowledge without weight updates).
