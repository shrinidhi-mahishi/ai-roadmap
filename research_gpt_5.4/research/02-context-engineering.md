# Research: Context Engineering - Prompting, context management, compression, caching

**Date researched**: 2026-08-21  
**Sources consulted**: 33

## 1. System Topology & Mechanics

- LangChain defines context engineering as building dynamic systems that provide "the right information and tools, in the right format" to the model, and its current architecture splits context into static runtime context, dynamic runtime state, and dynamic cross-conversation context. ([LangChain Context](https://docs.langchain.com/oss/python/concepts/context))
- In LangGraph, short-term context is thread-scoped state, while long-term context is stored as JSON documents in namespaced stores; this makes the operational topology "hot state in thread checkpoints, cold state in stores" rather than "entire history in the prompt every turn." ([LangChain Memory](https://docs.langchain.com/oss/python/concepts/memory), [LangGraph Add Memory](https://docs.langchain.com/oss/python/langgraph/add-memory))
- LangGraph checkpointers save a snapshot of graph state at each super-step and also persist node-level pending writes before the full checkpoint commits, which is a concrete mechanism for context durability and partial replay. ([LangGraph Checkpointers](https://docs.langchain.com/oss/python/langgraph/checkpointers), [LangGraph Persistence Source](https://github.com/langchain-ai/langgraph/blob/main/docs/docs/concepts/persistence.md))
- OpenAI prompt caching on GPT-5.6-and-later models uses exact matching at eligible cache breakpoints, has a strict minimum cacheable prefix of `1,024` tokens, and exposes cache state through `cached_tokens` and `cache_write_tokens`. ([OpenAI Prompt Caching](https://developers.openai.com/api/docs/guides/prompt-caching))
- Anthropic exposes two cache topologies: automatic caching, which places one moving breakpoint for you, and explicit breakpoints, where you place `cache_control` on content blocks; automatic caching consumes one of the `4` available breakpoint slots. ([Anthropic Prompt Caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching))
- Anthropic's explicit cache lookup is block-oriented, not semantic: writes happen only at breakpoints, and reads search backward up to `20` blocks for a previously written prefix hash. That means cacheability depends on message/block layout, not only token overlap. ([Anthropic Prompt Caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching))
- Gemini exposes both implicit caching and explicit cache resources. Implicit caching is automatic on Gemini `2.5+`; explicit caching creates a reusable cache object with managed TTL and explicit reference semantics. ([Gemini Context Caching Guide](https://ai.google.dev/gemini-api/docs/generate-content/caching), [Gemini Enterprise Context Caching](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/context-cache/context-cache-overview))
- Official prompting guidance across Anthropic and Google converges on the same packing rule for large contexts: put the long source material first and the specific question/instructions at the end. Anthropic reports up to `30%` quality improvement from placing the query at the end for complex multi-document inputs. ([Anthropic Prompting Best Practices](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices), [Gemini Prompt Design Strategies](https://ai.google.dev/gemini-api/docs/prompting-strategies))
- Both Anthropic and Google recommend strong structural delimiters for large prompts, especially XML-style sections for documents, instructions, and metadata; the mechanical point is to isolate data from instructions so retrieval context does not double as executable instruction space. ([Anthropic Prompting Best Practices](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices), [Gemini Structure Prompts](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/prompts/structure-prompts))

## 2. Token Economics & NFR Metrics

- A reusable costing formula for exact-prefix caching is: `cost_per_1k_exec = 1000 * ((uncached_input * input_rate) + (cached_read * cached_rate) + (cache_write * write_rate) + (output_tokens * output_rate)) / 1_000_000`. This is [inferred] directly from vendor billing models that separate uncached input, cached reads, cache writes, and outputs. ([OpenAI Prompt Caching](https://developers.openai.com/api/docs/guides/prompt-caching), [OpenAI Pricing](https://developers.openai.com/api/docs/pricing), [Anthropic Prompt Caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching), [Anthropic Pricing](https://platform.claude.com/docs/en/about-claude/pricing))
- OpenAI's published cache economics for GPT-5.6-and-later families are unusually explicit: cached reads bill at `0.1x` the uncached input rate, cache writes bill at `1.25x`, and exact TTL can be set to `30 minutes` via `prompt_cache_options.ttl`. ([OpenAI Prompt Caching](https://developers.openai.com/api/docs/guides/prompt-caching))
- Anthropic's cache multipliers are `1.25x` base input for `5-minute` writes, `2x` for `1-hour` writes, and `0.1x` for reads. The break-even point is therefore the second use for a `5-minute` cache and the third use for a `1-hour` cache. [inferred] ([Anthropic Prompt Caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching))
- Anthropic's minimum cacheable prefix is model-specific: `1,024` tokens for current Sonnet/Opus 4.8-era families listed in the docs, but `4,096` for Claude Opus `4.6`, Claude Opus `4.5`, and Claude Haiku `4.5`. That materially changes whether short enterprise policies or tool manifests are worth caching. ([Anthropic Prompt Caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching))
- Gemini explicit caching defaults to a `1 hour` TTL if not set, supports TTL mutation after creation, enforces a minimum cache duration of `1 minute`, and has no documented maximum duration. Minimum cache size is `2,048` tokens for Gemini `2.x` families and `4,096` for Gemini `3` families, with some previews requiring `6,144`. ([Gemini Context Caching Guide](https://ai.google.dev/gemini-api/docs/generate-content/caching), [Gemini Enterprise Context Caching](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/context-cache/context-cache-overview))
- Gemini's economic model differs from OpenAI/Anthropic exact-prefix caches: you pay the normal input rate to create the cache, then a discounted cache-use rate plus storage rent per million tokens per hour. Google documents `90%` cache-use discounts on Gemini `2.5+` and `75%` on Gemini `2.0` models for explicit caching. ([Gemini Enterprise Context Caching](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/context-cache/context-cache-overview), [Gemini Pricing](https://ai.google.dev/gemini-api/docs/pricing.md.txt))
- Google's pricing page shows storage rent is not negligible for long-lived caches: for some Gemini `2.5 Pro` tiers, explicit cache usage is priced at `$0.20` per million cached tokens (for prompts `<=200k` tokens) plus `$4.50` per million tokens per hour of storage. Exact figures vary by model tier and prompt size. ([Gemini Pricing](https://ai.google.dev/gemini-api/docs/pricing.md.txt))
- Anthropic rate limits are cache-aware in a way that directly affects NFR planning: for most current Claude models, `cache_read_input_tokens` do **not** count toward ITPM. Anthropic's own example says a `2,000,000` ITPM limit with an `80%` hit rate can process about `10,000,000` total input tokens/minute. ([Anthropic Rate Limits](https://platform.claude.com/docs/en/api/rate-limits))
- OpenAI exposes rate-limit telemetry through `x-ratelimit-*` headers and `Retry-After`; these are the primary feedback loops for runtime admission control and deadline management. ([OpenAI Rate Limits](https://developers.openai.com/api/docs/guides/rate-limits))
- Compression is still a valid economic lever when exact-prefix reuse is low. LLMLingua reports up to `20x` prompt compression with little performance loss on its workloads, and LongLLMLingua reports up to `21.4%` accuracy gain on NaturalQuestions with about `4x` fewer tokens, `94.0%` cost reduction on LooGLE, and `1.4x-2.6x` end-to-end latency improvement for `~10k`-token prompts compressed `2x-6x`. ([LLMLingua](https://aclanthology.org/2023.emnlp-main.825/), [LongLLMLingua](https://aclanthology.org/2024.acl-long.91))
- Public primary sources remain weak on provider p50/p95/p99 latency under production load.  
  > Limited public data available for percentile latency SLAs by model family; vendor docs publish pricing, quotas, and qualitative speed guidance far more often than hard latency distributions. ([OpenAI Rate Limits](https://developers.openai.com/api/docs/guides/rate-limits), [Anthropic Rate Limits](https://platform.claude.com/docs/en/api/rate-limits), [Gemini Long Context](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/long-context))

## 3. Distributed Resilience & State

- LangGraph's checkpoint model is the clearest public reference implementation for durable context orchestration: each super-step produces a checkpoint tied to a `thread_id`, and successful node writes are durable even if another node in the same super-step fails later. ([LangGraph Checkpointers](https://docs.langchain.com/oss/python/langgraph/checkpointers))
- Because LangGraph separates thread checkpoints from long-term stores, it can recover short-lived conversational state and durable profile/memory state independently. That is a stronger resilience pattern than flattening both into one prompt transcript. [inferred] ([LangChain Memory](https://docs.langchain.com/oss/python/concepts/memory), [LangGraph Add Memory](https://docs.langchain.com/oss/python/langgraph/add-memory))
- Anthropic's `20`-block backward lookup window is a real distributed-state constraint: if a growing conversation moves the newest breakpoint more than `20` blocks past the last cache write, the prior cache entry becomes invisible unless you added another breakpoint earlier. ([Anthropic Prompt Caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching))
- OpenAI exact-prefix caching is also stateful in practice. The docs recommend reusing the same `prompt_cache_key` for requests that share long prefixes and monitoring `cache_write_tokens` versus `cached_tokens`; if writes stay high and reads stay low, you are effectively running a thrashing cache. ([OpenAI Prompt Caching](https://developers.openai.com/api/docs/guides/prompt-caching))
- Exact-prefix caches are serialization-sensitive: Anthropic states that changing any block at or before the breakpoint produces a different hash, and OpenAI requires an exact matching prefix at eligible breakpoints. Stable canonical serialization for tools, schemas, and examples is therefore an operational requirement, not a cosmetic choice. [inferred] ([Anthropic Prompt Caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching), [OpenAI Prompt Caching](https://developers.openai.com/api/docs/guides/prompt-caching))
- Gemini explicit caches externalize context into a first-class resource with update/delete operations and independent expiration, which is a better fit for multi-request document sessions than rewriting a giant prompt every turn. [inferred] ([Gemini API Caching Reference](https://ai.google.dev/api/caching), [Gemini Context Caching Guide](https://ai.google.dev/gemini-api/docs/generate-content/caching))
- Semantic caching introduces a different resilience profile than exact-prefix caching. Redis LangCache supports `exact` and `semantic` search strategies, configurable similarity thresholds, TTLs, and eviction policies; that broadens hit rate but requires precision/recall tuning so "close enough" responses do not become wrong answers. ([Redis LangCache Docs](https://redis.io/docs/latest/develop/ai/context-engine/langcache/), [LangCache API Examples](https://redis.io/docs/latest/develop/ai/langcache/api-examples/))
- Provider docs do not expose internals for leader election, distributed locks, or replay journals behind hosted caches.  
  > Limited public data available for provider-internal replication, consistency guarantees, or cross-region cache invalidation semantics for OpenAI, Anthropic, or Gemini managed caches.

## 4. Enterprise Security & Governance

- OpenAI's agent-safety guidance treats prompt injection as a context-engineering problem, not just a moderation problem: untrusted external data should not be concatenated into developer instructions, and data should flow between nodes through structured outputs rather than freeform text channels. ([OpenAI Safety in Building Agents](https://developers.openai.com/api/docs/guides/agent-builder-safety))
- Anthropic's guardrail guidance is even more concrete for context isolation: third-party or tool-returned content should be passed back only inside `tool_result` blocks, never in `system` prompts or plain user text, and Anthropic recommends screening tool outputs with a smaller model using structured outputs before the main model sees them. ([Anthropic Mitigate Jailbreaks](https://platform.claude.com/docs/en/test-and-evaluate/strengthen-guardrails/mitigate-jailbreaks))
- Anthropic's `allowed_callers` is not a hard security boundary; the programmatic tool-calling docs explicitly say clients should still be ready to handle direct `tool_use` for any defined tool. That means tool visibility hints must be backed by real policy enforcement outside the model. ([Anthropic Programmatic Tool Calling](https://platform.claude.com/docs/en/agents-and-tools/tool-use/programmatic-tool-calling))
- MCP now provides the strongest primary-source pattern for Zero-Trust tool connectivity: OAuth `2.1`, PKCE with `S256`, Protected Resource Metadata (`RFC9728`), Authorization Server Metadata / OIDC discovery, and Resource Indicators (`RFC8707`) are all explicit requirements when authorization is implemented. ([MCP Authorization Spec](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization))
- MCP security best practices explicitly forbid token passthrough. Servers must reject tokens not issued for themselves and must use separate upstream tokens when they call downstream APIs; this is aimed directly at the confused-deputy failure mode for agent/tool gateways. ([MCP Authorization Spec](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization), [MCP Security Best Practices](https://modelcontextprotocol.org/docs/tutorials/security/security_best_practices))
- Google recommends explicitly grounding the model with instructions like "rely only on the provided context" and to state when information is unavailable. That is a low-cost governance control for reducing answer fabrication in enterprise retrieval flows. ([Gemini Prompt Design Strategies](https://ai.google.dev/gemini-api/docs/prompting-strategies), [Gemini 3 Prompting Guide](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/start/gemini-3-prompting-guide))
- Anthropic and OpenAI both recommend least-privilege tool access plus human confirmation before consequential actions; in governance terms, context shaping reduces risk only when paired with permission shaping. ([OpenAI Safety in Building Agents](https://developers.openai.com/api/docs/guides/agent-builder-safety), [Anthropic Engineering: How We Contain Claude](https://www.anthropic.com/engineering/how-we-contain-claude))
- Public material remains thin on provider-side PII redaction internals, immutable audit-log schemas, and exact sandbox substrates for hosted tool execution.  
  > Limited public data available for classifier architectures, redact-before-log pipelines, or whether hosted tool runtimes use containers, microVMs, or WASM as the primary isolation boundary.

## 5. Production Failure Modes

- Long context does not equal robust long-context reasoning. "Lost in the Middle" found that performance is often highest when relevant information appears at the beginning or end of context and degrades significantly when the evidence is in the middle. ([Lost in the Middle](https://aclanthology.org/2024.tacl-1.9/))
- The same paper also found that open-domain QA reader performance saturates far before retriever recall, which means "retrieve more documents" can stop helping long before the retriever itself stops finding relevant material. ([Lost in the Middle](https://aclanthology.org/2024.tacl-1.9/))
- RULER shows why needle-in-a-haystack tests are insufficient: despite near-perfect scores on vanilla retrieval tests, almost all evaluated long-context models degraded as context length grew, and only about half of the `17` tested models maintained satisfactory performance at `32K`. ([RULER](https://arxiv.org/abs/2404.06654), [RULER Repository](https://github.com/nvtransfer/RULER))
- Google's enterprise docs claim near-perfect retrieval (`>99%`) for Gemini's long context window, but retrieval success is narrower than end-task reasoning success on tasks like aggregation or multi-hop tracing. Treat retrieval claims and benchmarked reasoning claims as different metrics. [inferred] ([Gemini Long Context](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/long-context), [RULER](https://arxiv.org/abs/2404.06654), [Lost in the Middle](https://aclanthology.org/2024.tacl-1.9/))
- Anthropic's cache failure mode is silent miss, not explicit error: if the last shared prefix is more than `20` blocks behind the current breakpoint, or if the breakpoint is placed after variable content, the request still succeeds but the cache hit disappears. ([Anthropic Prompt Caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching))
- OpenAI exact-prefix caching has a similar silent-failure shape: requests continue to work even if `cached_tokens` drops to zero because the shared prefix did not reach `1,024` tokens, the wrong `prompt_cache_key` was used, or the prefix changed before the breakpoint. ([OpenAI Prompt Caching](https://developers.openai.com/api/docs/guides/prompt-caching))
- Compression failure is usually quality drift, not infrastructure failure. LongLLMLingua reports that entropy-only compression methods can perform poorly in noisy long-context tasks because they keep too much irrelevant material; its gains come from question-aware compression and document reordering. ([LongLLMLingua](https://aclanthology.org/2024.acl-long.91))
- Prompt injection remains a production failure mode whenever retrieved text or tool outputs are treated as high-trust instructions. OpenAI and Anthropic both explicitly recommend isolating untrusted data and constraining inter-node communication with schemas. ([OpenAI Safety in Building Agents](https://developers.openai.com/api/docs/guides/agent-builder-safety), [Anthropic Mitigate Jailbreaks](https://platform.claude.com/docs/en/test-and-evaluate/strengthen-guardrails/mitigate-jailbreaks))
- Cascading timeout/retry storms are still governed by classic distributed-systems rules: OpenAI says to honor `Retry-After` and otherwise use exponential backoff with jitter, while Anthropic documents short-interval enforcement and acceleration limits even below minute-level averages. ([OpenAI Rate Limits](https://developers.openai.com/api/docs/guides/rate-limits), [OpenAI Error Codes](https://developers.openai.com/api/docs/guides/error-codes), [Anthropic Rate Limits](https://platform.claude.com/docs/en/api/rate-limits))
- Public incident post-mortems specific to context-cache corruption, summarization drift, or prompt-packing regressions remain scarce.  
  > Limited public data available for vendor post-mortems on cache invalidation bugs, prompt-compression regressions, or long-context production outages.

## 6. Enterprise System Design Scenarios

- **Scenario A: high-volume support or FAQ assistant.** Put policies, style rules, and tool schemas in an exact-prefix cache; add a semantic cache in front of the model for common paraphrases. Exact-prefix caching gives deterministic savings when the prompt is stable, while semantic caching can return millisecond answers for near-duplicate requests. ([OpenAI Prompt Caching](https://developers.openai.com/api/docs/guides/prompt-caching), [Anthropic Prompt Caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching), [Redis LangCache Docs](https://redis.io/docs/latest/develop/ai/context-engine/langcache/))
- **Scenario B: chat-with-documents over a stable corpus.** For repeated interaction with the same PDFs/transcripts, Gemini explicit caches or Anthropic/OpenAI prompt caches are usually simpler than building full RAG first. Compression becomes the next lever only when reuse is low, cache thresholds are not met, or cost/latency still miss targets after caching. ([Gemini Enterprise Context Caching](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/context-cache/context-cache-overview), [OpenAI Prompt Caching](https://developers.openai.com/api/docs/guides/prompt-caching), [Anthropic Prompt Caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching), [LongLLMLingua](https://aclanthology.org/2024.acl-long.91))
- **Scenario C: regulated enterprise agent.** Use an MCP/OAuth gateway for tools, never trust `allowed_callers` alone, pass external content only as low-trust data, and require confirmations for write actions. This architecture treats context assembly and authorization as separate control planes. ([MCP Authorization Spec](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization), [MCP Security Best Practices](https://modelcontextprotocol.org/docs/tutorials/security/security_best_practices), [Anthropic Programmatic Tool Calling](https://platform.claude.com/docs/en/agents-and-tools/tool-use/programmatic-tool-calling), [OpenAI Safety in Building Agents](https://developers.openai.com/api/docs/guides/agent-builder-safety))
- **Scenario D: long-running agent workflow with memory.** Use LangGraph thread checkpoints for hot trajectory state, long-term stores for user/org memory, and explicit summarize/trim policies as windows fill. This is a better pattern than replaying the entire transcript each turn because it supports resume, inspection, and bounded prompt growth. ([LangGraph Checkpointers](https://docs.langchain.com/oss/python/langgraph/checkpointers), [LangGraph Add Memory](https://docs.langchain.com/oss/python/langgraph/add-memory))
- **Scenario E: cost-sensitive research or analytics agent.** First try long-context prompt ordering and quote-grounding; if quality is acceptable, add exact-prefix caching; if cache reuse is low, add question-aware compression; if reasoning still degrades in the middle, switch to retrieval or chunk-select flows. This ordering follows the evidence: structure and grounding are cheap, caching improves both cost and throughput, and compression helps but can distort signal if applied blindly. [inferred] ([Anthropic Prompting Best Practices](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices), [Gemini Prompt Design Strategies](https://ai.google.dev/gemini-api/docs/prompting-strategies), [LongLLMLingua](https://aclanthology.org/2024.acl-long.91), [Lost in the Middle](https://aclanthology.org/2024.tacl-1.9/))
- **Trade-off summary.** Exact-prefix caching has the best determinism and lowest verification burden but is fragile to formatting drift; semantic caching broadens hit rate but needs quality gates; brute-force long context is the easiest developer experience but is exposed to position bias; compression reduces cost and latency but should be query-aware to avoid deleting the evidence that matters. [inferred] ([OpenAI Prompt Caching](https://developers.openai.com/api/docs/guides/prompt-caching), [Anthropic Prompt Caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching), [Redis LangCache Docs](https://redis.io/docs/latest/develop/ai/context-engine/langcache/), [LongLLMLingua](https://aclanthology.org/2024.acl-long.91), [Lost in the Middle](https://aclanthology.org/2024.tacl-1.9/))
- Public sources do not provide enough hard numbers for concurrent-agent memory footprint, cache replication lag, or provider-managed cache hit-rate distributions by workload.  
  > Limited public data available for enterprise-scale capacity planning beyond pricing, minimum thresholds, and high-level quota documents.
