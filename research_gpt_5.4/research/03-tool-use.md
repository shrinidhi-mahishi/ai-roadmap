# Research: Tool Use - APIs, function calling, browser, code execution

**Date researched**: 2026-08-21
**Sources consulted**: 18

## 1. System Topology & Mechanics

- OpenAI's `Responses` stack exposes tool use through a single `tools` surface that can mix built-in tools, custom function tools, remote MCP servers, computer use, and `tool_search`; the model can choose automatically or be constrained with `tool_choice`. Function tools are JSON-Schema-defined interfaces, and `tool_search` is available only on `gpt-5.4` and later. [OpenAI tools](https://developers.openai.com/api/docs/guides/tools), [OpenAI function calling](https://developers.openai.com/api/docs/guides/function-calling)
- Anthropic splits tool execution into two topologies: client tools, where Claude emits `tool_use` blocks and the application must execute them and return `tool_result`, and server tools, where Anthropic executes the operation internally and returns results in the same response. That is a real control-plane/data-plane split: orchestration stays with the model/API, while execution can live either in the caller or on the provider side. [Anthropic tool use overview](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview)
- Anthropic's `browser_toolset_20260801` is a browser-scoped client toolset with 27 default member tools and 4 optional members; it acts on page structure (accessibility tree, forms, tabs, element refs) as well as screenshots. Anthropic's `computer_toolset_20260801` is a desktop-scoped client toolset with 17 member tools such as `screenshot`, `left_click`, `type`, and `zoom`. Both require the caller to run the executor. [Anthropic browser use tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/browser-use-tool), [Anthropic computer use tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/computer-use-tool)
- OpenAI's computer-use loop is explicitly iterative: send a task with the `computer` tool enabled, inspect the returned `computer_call`, execute the full `actions[]` array in order, capture a fresh screenshot, send `computer_call_output`, and repeat until the model stops returning computer calls. OpenAI recommends a Playwright or Selenium harness for browser automation and an isolated browser or VM for safety. [OpenAI computer use](https://developers.openai.com/api/docs/guides/tools-computer-use)
- Anthropic's code execution is server-side: adding `code_execution_20260521` gives Claude sandboxed bash and file-manipulation sub-tools, and the provider runs the container. In contrast, Anthropic's browser/computer/bash/text-editor toolsets are client-side schemas that the application executes. [Anthropic code execution tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/code-execution-tool), [Anthropic tool use overview](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview)
- MCP's transport model is protocol-first rather than vendor-first. The current spec defines a JSON-RPC-based base protocol plus lifecycle/capability negotiation, and says HTTP transports should use the MCP authorization framework while STDIO transports should instead source credentials from the environment. [MCP base spec](https://modelcontextprotocol.io/specification/2025-11-25/basic/index), [MCP authorization](https://modelcontextprotocol.io/specification/draft/basic/authorization)
- Browser automation harnesses often sit on top of the Chrome DevTools Protocol, which exposes browser/page targets over HTTP and WebSocket endpoints. The protocol's tip-of-tree surface is not backward-compatible, so production systems should pin to known browser/client combinations rather than assume latest-CDP stability. [Chrome DevTools Protocol](https://chromedevtools.github.io/devtools-protocol/)

## 2. Token Economics & NFR Metrics

> ⚠️ Limited public data available for p50/p95/p99 latency benchmarks across tool loops. The primary vendors publish pricing, rate limits, cache behavior, and some optimization guidance, but not comprehensive production latency distributions for function calling, browser use, or code execution.

- OpenAI states that callable function definitions are injected into the prompt syntax the model was trained on, so tool definitions count against context limits and are billed as input tokens. OpenAI recommends limiting the number of up-front tools, shortening descriptions, or using `tool_search` to defer rarely used tools. [OpenAI function calling](https://developers.openai.com/api/docs/guides/function-calling)
- OpenAI prompt caching is automatic on recent models. For GPT-5.6 and later, cache breakpoints can be explicit, minimum cacheable prefix is 1,024 tokens, cache reads are billed at `0.1x` uncached input rate, and cache writes are billed at `1.25x` uncached input rate. OpenAI also says older prompt caches are typically cleared after 5-10 minutes of inactivity and always within 1 hour of last use. [OpenAI prompt caching guide](https://developers.openai.com/api/docs/guides/prompt-caching), [OpenAI prompt caching announcement](https://openai.com/index/api-prompt-caching/)
- OpenAI's current hosted-tool price sheet is concrete: web search costs `$10 / 1k calls`; file search tool calls cost `$2.50 / 1k calls`; Hosted Shell and Code Interpreter containers cost `$0.03`, `$0.12`, `$0.48`, and `$1.92` per 20-minute session for `1 GB`, `4 GB`, `16 GB`, and `64 GB` respectively, with billing by the minute and a 5-minute minimum for eligible sessions. [OpenAI pricing](https://developers.openai.com/api/docs/pricing)
- OpenAI Code Interpreter runs inside a fully sandboxed container, supports `1g`, `4g`, `16g`, and `64g` memory tiers, and can reuse an active container from a prior `code_interpreter_call` in context. That makes session reuse a first-order cost lever, not just a convenience feature. [OpenAI Code Interpreter](https://developers.openai.com/api/docs/guides/tools-code-interpreter)
- Anthropic tool-use cost includes: input tokens in the `tools` parameter, output tokens, `tool_use` blocks, `tool_result` blocks, and a model-specific tool-use system prompt. Anthropic publishes the tool-use system prompt overhead itself: Claude Opus 5 adds `286` tokens for `auto/none` or `406` for `any/tool`; Claude Sonnet 5 adds `354` or `474`; Claude Haiku 4.5 adds `496` or `588`. [Anthropic pricing](https://platform.claude.com/docs/en/about-claude/pricing)
- Anthropic publishes unusually concrete toolset overhead numbers. Declaring `browser_toolset_20260801` adds about `6,610` input tokens on Claude Opus 5 / Opus 4.8 and about `6,670` on Claude Sonnet 5; enabling all four optional browser members adds about `880` more tokens. Declaring `computer_toolset_20260801` adds about `4,520` input tokens on Claude Opus 5 / Opus 4.8 and about `4,590` on Claude Sonnet 5; disabling `zoom` removes about `410` tokens. [Anthropic browser use tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/browser-use-tool), [Anthropic computer use tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/computer-use-tool)
- Anthropic prompt caching supports a default 5-minute TTL and an optional 1-hour TTL. Cache writes cost `1.25x` base input price for 5-minute entries or `2x` for 1-hour entries; cache hits cost `0.1x` base input price. Anthropic measures lifetime from request start, not response end, so long generations eat into TTL. [Anthropic prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching), [Anthropic pricing](https://platform.claude.com/docs/en/about-claude/pricing)
- Anthropic's rate limits are token-bucket-based and published by usage tier. For major current model families at Start tier, the documented envelope is `1,000 RPM`, `2,000,000 ITPM`, and `400,000 OTPM`; Build lifts that to `5,000 / 5,000,000 / 1,000,000`; Scale lifts it to `10,000 / 10,000,000 / 2,000,000`. Anthropic also documents that short bursts can be enforced as per-second equivalents and that acceleration spikes can trigger additional `429`s. [Anthropic rate limits](https://platform.claude.com/docs/en/api/rate-limits)
- Anthropic's programmatic tool calling is one of the few places with benchmark-like published numbers: on BrowseComp and DeepSearchQA, Anthropic reports an average `11%` quality improvement with `24%` fewer input tokens versus basic search-tool use alone. [Anthropic programmatic tool calling](https://platform.claude.com/docs/en/agents-and-tools/tool-use/programmatic-tool-calling)
- Cost formulas that are explicit enough for architecture work:
  - `OpenAI function-tool cost / 1k runs = model token cost (uncached input + 0.1 * cached reads + 1.25 * cache writes + output) + hosted tool fees`, where hosted tool fees can add `$10 / 1k` web searches or per-container runtime fees. [OpenAI function calling](https://developers.openai.com/api/docs/guides/function-calling), [OpenAI prompt caching guide](https://developers.openai.com/api/docs/guides/prompt-caching), [OpenAI pricing](https://developers.openai.com/api/docs/pricing) [inferred]
  - `Fresh OpenAI 1 GB code-execution floor = 5 minutes * ($0.03 / 20 minutes) = $0.0075 per run = $7.50 / 1k runs` if every execution creates a new eligible container and ends quickly. [OpenAI pricing](https://developers.openai.com/api/docs/pricing) [inferred]
  - `Anthropic Sonnet 5 browser-toolset overhead = 6,670 input tokens * $2 / MTok = about $0.01334 per uncached request = $13.34 / 1k requests` before screenshots, user prompt, output, and tool results. `Anthropic Sonnet 5 computer-toolset overhead = 4,590 * $2 / MTok = about $9.18 / 1k requests` under the same assumption. [Anthropic browser use tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/browser-use-tool), [Anthropic computer use tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/computer-use-tool), [Anthropic pricing](https://platform.claude.com/docs/en/about-claude/pricing) [inferred]

## 3. Distributed Resilience & State

- LangGraph's checkpointers persist a full `StateSnapshot` at every super-step boundary and also persist per-task writes within a super-step. If one node fails after siblings already completed, those successful writes are durable as pending writes and do not need to be recomputed on resume. `thread_id` is mandatory for persistence and replay. [LangGraph checkpointers](https://docs.langchain.com/oss/python/langgraph/checkpointers)
- OpenAI's Agents SDK exposes resumable execution at approval boundaries: when a tool call needs review, the run returns `interruptions` plus resumable `state`; the same run is resumed from that snapshot after approval or rejection. The SDK also traces tool calls, handoffs, and guardrails by default. [OpenAI Agents SDK](https://developers.openai.com/api/docs/guides/agents), [OpenAI guardrails and human review](https://developers.openai.com/api/docs/guides/agents/guardrails-approvals), [OpenAI Agents tracing](https://openai.github.io/openai-agents-python/tracing/)
- Anthropic's `code_execution_20260120` and later can preserve Python interpreter state across requests when the same container is reused, which reduces repeated setup overhead and allows multi-step tool programs to build on prior state. That is weaker than a full workflow checkpoint, but it is a real stateful execution primitive. [Anthropic code execution tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/code-execution-tool)
- MCP's auth flow adds resilience through standards-based discovery rather than hard-coded endpoints: protected-resource metadata points clients at authorization servers, clients must support both OAuth Authorization Server Metadata and OIDC discovery, and the token request must bind to the target `resource`. [MCP authorization](https://modelcontextprotocol.io/specification/draft/basic/authorization)
- Durable orchestration details for vendor-hosted tool loops are not deeply public. OpenAI and Anthropic document resumable states, containers, and agent loops, but they do not publicly describe Temporal/Kafka/event-sourcing internals for hosted tool dispatch. [OpenAI Agents SDK](https://developers.openai.com/api/docs/guides/agents), [Anthropic tool use overview](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview)

## 4. Enterprise Security & Governance

- MCP's emerging Zero-Trust baseline is explicit: OAuth 2.1 for HTTP transports, Protected Resource Metadata (`RFC 9728`) for discovery, `resource` indicators (`RFC 8707`) to bind tokens to a specific MCP server, PKCE with `S256`, and least-privilege scope guidance via `WWW-Authenticate`. [MCP authorization](https://modelcontextprotocol.io/specification/draft/basic/authorization), [MCP auth security considerations](https://modelcontextprotocol.io/specification/draft/basic/authorization/security-considerations)
- OpenAI recommends running computer use in an isolated browser or VM, passing an empty `env`, disabling extensions and local file-system access where possible, keeping humans in the loop for high-impact actions, and treating page content as untrusted input. [OpenAI computer use](https://developers.openai.com/api/docs/guides/tools-computer-use)
- Anthropic recommends a dedicated VM or container with minimal privileges, avoiding access to sensitive credentials, allowlisting internet domains, and requiring human confirmation for cookies, financial transactions, and terms acceptance. Anthropic also says screenshot-based prompt-injection classifiers can steer the model to ask for user confirmation before proceeding. [Anthropic computer use tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/computer-use-tool)
- Anthropic's code execution tool runs in a secure sandboxed container with no internet access; only pre-installed libraries are available at runtime. That meaningfully constrains exfiltration and supply-chain risk, but it also limits live package fetches and outbound API access. [Anthropic code execution tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/code-execution-tool)
- OpenAI's Agents SDK provides three guardrail layers: input guardrails, output guardrails, and tool guardrails. Human review is a separate pause/resume path for sensitive side effects. On the observability side, OpenAI's tracing records function spans, guardrail spans, handoff spans, and agent spans, and tracing can be configured to exclude sensitive payloads. [OpenAI guardrails and human review](https://developers.openai.com/api/docs/guides/agents/guardrails-approvals), [OpenAI Agents tracing](https://openai.github.io/openai-agents-python/tracing/)
- Public vendor docs here are thin on PII-redaction internals and immutable audit-log schemas. They document approval/trace surfaces, but not a canonical SOC2/HIPAA/GDPR audit event schema for tool calls. [OpenAI guardrails and human review](https://developers.openai.com/api/docs/guides/agents/guardrails-approvals), [OpenAI Agents tracing](https://openai.github.io/openai-agents-python/tracing), [Anthropic tool use overview](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview)

## 5. Production Failure Modes

- OpenAI documents a concrete failure mode for JSON mode: if you enable JSON mode without explicitly instructing the model to produce JSON in the message/input context, the model may emit an effectively unending whitespace stream until token limits stop it. OpenAI also recommends `strict: true` because strict mode rejects incompatible schemas up front and enforces argument conformance instead of best-effort matching. [OpenAI function-calling help](https://help.openai.com/en/articles/8555517-function-calling-in-the-openai-api), [OpenAI function calling](https://developers.openai.com/api/docs/guides/function-calling)
- Large tool surfaces directly increase context pressure. OpenAI says tool definitions are billed as input tokens and count against context, so excessive tool catalogs can degrade quality or force truncation; `tool_search` is the official mitigation. [OpenAI function calling](https://developers.openai.com/api/docs/guides/function-calling)
- Anthropic documents control over runaway multi-tool fan-out: `disable_parallel_tool_use: true` limits Claude to at most one tool call per turn for the client-tool loop. That does not solve all infinite-loop cases, but it is a built-in guard against explosive parallel actions. [Anthropic tool use overview](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview)
- Cache misses are easy to trigger accidentally. OpenAI requires exact prefix matches, stable tools/schemas at the front of the prompt, and consistent `prompt_cache_key` usage for optimal reuse. Anthropic measures cache lifetime from request start; a 4-minute streaming response on a 5-minute TTL leaves roughly 1 minute to reuse the cache. [OpenAI prompt caching guide](https://developers.openai.com/api/docs/guides/prompt-caching), [Anthropic prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)
- Prompt injection is a first-class failure mode for visual/browser agents. OpenAI explicitly says page content should be treated as untrusted input; Anthropic says content on webpages or in screenshots may override instructions or induce mistakes and recommends isolation plus human confirmation. [OpenAI computer use](https://developers.openai.com/api/docs/guides/tools-computer-use), [Anthropic computer use tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/computer-use-tool)
- Rate limiting itself can cascade into availability failures. Anthropic documents token-bucket enforcement, short-interval burst limits, and acceleration limits; OpenAI documents `Retry-After` plus `x-ratelimit-*` headers and says official SDKs automatically honor retry guidance for eligible rate-limit errors. [Anthropic rate limits](https://platform.claude.com/docs/en/api/rate-limits), [OpenAI rate limits](https://developers.openai.com/api/docs/guides/rate-limits)
- Public postmortems for tool-loop incidents are sparse in the official material reviewed here. Teams should assume missing external data and instrument their own loop-termination, approval, timeout-budget, and schema-validation telemetry accordingly. [OpenAI Agents tracing](https://openai.github.io/openai-agents-python/tracing), [Anthropic tool use overview](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview) [inferred]

## 6. Enterprise System Design Scenarios

- For API-first enterprise workflows, JSON-Schema function calling is the lowest-friction pattern: it avoids screenshots, keeps actions structured, supports strict validation, and can be paired with deferred tool loading (`tool_search`) plus SDK approvals and traces. That is the best fit for CRMs, ticketing systems, billing APIs, and internal service actions. [OpenAI function calling](https://developers.openai.com/api/docs/guides/function-calling), [OpenAI tools](https://developers.openai.com/api/docs/guides/tools), [OpenAI guardrails and human review](https://developers.openai.com/api/docs/guides/agents/guardrails-approvals) [inferred]
- For web-only SaaS workflows where a DOM is available, Anthropic's browser toolset or an OpenAI computer-use harness backed by Playwright/CDP is usually better than full desktop control because the browser surface exposes page structure and element references instead of relying only on pixels. [Anthropic browser use tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/browser-use-tool), [OpenAI computer use](https://developers.openai.com/api/docs/guides/tools-computer-use), [Chrome DevTools Protocol](https://chromedevtools.github.io/devtools-protocol/) [inferred]
- For legacy desktop apps, VDI sessions, or workflows crossing browser and native UI boundaries, desktop-style computer use is more flexible but carries higher prompt-injection and safety risk, and usually deserves stricter human approval thresholds. [OpenAI computer use](https://developers.openai.com/api/docs/guides/tools-computer-use), [Anthropic computer use tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/computer-use-tool) [inferred]
- For analysis-heavy or transformation-heavy tasks, server-side code execution is the most operationally compact pattern because it eliminates a local execution harness. Anthropic's version is internet-isolated; OpenAI's version exposes explicit container sizing and reuse semantics. That makes it a strong fit for ETL-like reasoning, CSV analysis, plotting, and code generation pipelines where external network calls are not required at runtime. [Anthropic code execution tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/code-execution-tool), [OpenAI Code Interpreter](https://developers.openai.com/api/docs/guides/tools-code-interpreter) [inferred]
- Capacity-planning heuristics that can be lifted directly into architecture estimates:
  - Anthropic Start tier already supports `1,000 RPM` and `2,000,000 ITPM` on current Sonnet/Opus/Haiku families, which is enough for many internal copilots but can be eaten quickly by screenshot-heavy browser flows. [Anthropic rate limits](https://platform.claude.com/docs/en/api/rate-limits)
  - Uncached browser-toolset overhead alone on Sonnet 5 is about `6.67M` input tokens per `1,000` requests, or about `$13.34 / 1k` requests before model output and screenshot/image costs. Uncached computer-toolset overhead alone is about `4.59M` input tokens per `1,000` requests, or about `$9.18 / 1k`. [Anthropic browser use tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/browser-use-tool), [Anthropic computer use tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/computer-use-tool), [Anthropic pricing](https://platform.claude.com/docs/en/about-claude/pricing) [inferred]
  - OpenAI's 1 GB code-execution floor is about `$7.50 / 1k` fresh short-lived runs, but container reuse can drive that lower on a per-task basis; larger memory tiers scale linearly from the published 20-minute prices. [OpenAI pricing](https://developers.openai.com/api/docs/pricing) [inferred]
- Decision matrix for enterprise architecture:
  - `Function calling`: best when a stable API exists; strongest schema governance; lowest token overhead relative to visual tools. [OpenAI function calling](https://developers.openai.com/api/docs/guides/function-calling), [Anthropic tool use overview](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview) [inferred]
  - `Browser use`: best when the target is web-native but lacks a good API; higher token overhead; moderate operational complexity; safer than full desktop when DOM-level controls exist. [Anthropic browser use tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/browser-use-tool) [inferred]
  - `Computer use`: best for cross-app or legacy UI automation; highest flexibility; highest safety burden and strongest need for approval gates. [OpenAI computer use](https://developers.openai.com/api/docs/guides/tools-computer-use), [Anthropic computer use tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/computer-use-tool) [inferred]
  - `Code execution`: best for bounded computation and file processing; strong sandbox properties; constrained by package/network availability. [Anthropic code execution tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/code-execution-tool), [OpenAI Code Interpreter](https://developers.openai.com/api/docs/guides/tools-code-interpreter) [inferred]
